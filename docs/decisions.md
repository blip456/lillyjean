# Decisions log

Decisions made during project kickoff (2026-10-07) and after the wireframe review round (2026-10-11, feedback
from the Product Owner, Jean and Lilly in `docs/wireframes/v1/feedback-*.md`). Each entry records what we chose,
the alternatives considered and why. Add a new entry instead of rewriting an old one when a decision changes.

## Product

| #   | Topic                  | Decision                                                                                                                                      | Notes                                                                                                              |
| --- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| P1  | Name for book lists    | **Readlist**                                                                                                                                  | Shortlisted alternatives: Stack, Lineup, Crate. Readlist was chosen for immediate clarity (playlist mental model). |
| P2  | Completing a challenge | Creator curates candidate books **and** a member may submit their own pick that fits the theme. Reading **one** book completes the challenge. | Own picks are visible to club members. Refined by P10–P12 (2026-10-11).                                            |
| P3  | Challenge timing       | Start date **required**, end date **optional**.                                                                                               | Without an end date a challenge stays active until completed.                                                      |
| P4  | Who creates challenges | **Official** (app-wide, admin-made, anyone can join) **and** user-made (personal or shared with one or more bookclubs).                       | Needs an admin role. Bookclub sharing superseded by P7 and P13 (2026-10-11).                                       |
| P5  | Book detail source     | Public book API in-app **+** "View on Goodreads" link-out.                                                                                    | Goodreads has no public API. Ratings refined by P17 (2026-10-11).                                                  |
| P6  | Bookclub hierarchy     | Flat: every member sees everything, including each member's challenge progress.                                                               | Superseded by P7 (2026-10-11): bookclubs move to Later; friends come first.                                        |

## Authentication

| #   | Topic                    | Decision                                                                                                                                                                                                    | Notes                                                                                                            |
| --- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| A1  | Login identifier         | **Email + password** (Supabase native).                                                                                                                                                                     | Username login can be added later via a server-side lookup if users ask for it.                                  |
| A2  | Username                 | Required, chosen in onboarding step 1 ("Library card"), not on the signup form.                                                                                                                             | Same step will serve Google sign-ups later. Invites reference user IDs, so usernames can be renamed safely.      |
| A3  | Email confirmation       | **Required**, via a **6-digit code entered in the app**.                                                                                                                                                    | Links break inside installed iOS PWAs (separate storage). Real emails are needed for invites and password reset. |
| A4  | Google login             | Later. The welcome/login screens reserve a slot for it.                                                                                                                                                     | Supabase auto-links a Google identity to an existing verified email.                                             |
| A5  | Password policy          | Minimum 12 characters, no composition rules, paste allowed.                                                                                                                                                 | NIST 800-63B-4 and WCAG 2.2 (accessible authentication).                                                         |
| A6  | Username rules           | 3–20 characters: lowercase letters, digits, dot and underscore. Unique (case-insensitive). Changeable at most once every 30 days.                                                                           | 2026-10-11. PO: standard and secure. L: no rules.                                                                |
| A7  | Existing email on signup | **Neutral** message ("check your mailbox"); never reveal whether an account exists.                                                                                                                         | 2026-10-11. PO + L.                                                                                              |
| A8  | Email change             | Allowed, with verification of the new address.                                                                                                                                                              | 2026-10-11. PO.                                                                                                  |
| A9  | Delete account           | Soft delete at once, hard delete after 14 days. Personal data is removed; shared contributions (ratings, shared challenges) stay and are shown as "Kicked out of the library".                              | 2026-10-11. PO. J: immediate removal. L: anonymise.                                                              |
| A10 | Sessions                 | No "sign out everywhere"; sign out on this device only.                                                                                                                                                     | 2026-10-11. PO.                                                                                                  |
| A11 | Splash                   | Animation on the very first open only ("unboxing"); afterwards a plain, fast start.                                                                                                                         | 2026-10-11. PO.                                                                                                  |
| A12 | Email change setting     | Supabase **Secure email change off**: only the new address receives a code (implements A8). 2026-10-11.                                                                                                     | Sprint 2.                                                                                                        |
| A13 | Code entry               | One numeric field with one-time-code autofill, paste support and auto-submit on the 6th digit, instead of six separate boxes. Codes are valid **15 minutes**; resend after a **60 s** cooldown. 2026-10-11. | Sprint 2. Accessible and works with iOS/Android code autofill.                                                   |

## Technical

| #   | Topic                | Decision                                                                                                                                                                                                                                                                                                    | Alternatives considered                                                                   |
| --- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| T1  | Frontend             | **Next.js 16** (App Router), TypeScript, Tailwind CSS v4                                                                                                                                                                                                                                                    | React + Vite SPA, SvelteKit 2, Flutter (web), React Router v7, Nuxt, TanStack Start, Expo |
| T2  | Backend              | Supabase Postgres + **row-level security**. The browser and server talk to Supabase directly for simple reads and writes. Business rules that must be atomic live in **Postgres functions** (RPC). Next.js Route Handlers / Server Actions are used only where secrets are needed (book API proxy, emails). | Separate API (Hono) — only worth it once a second client (native app) exists.             |
| T3  | Book data            | **Open Library** (CC0) primary, **Google Books** fallback. Results cached in our own `books` table; covers in Supabase Storage.                                                                                                                                                                             | Google Books only, ISBNdb (paid), Hardcover (no commercial use of ratings).               |
| T4  | Versioning           | **One shared semver version** for the whole app, in `package.json`.                                                                                                                                                                                                                                         | Separate web/api versions — can be split later if a native app appears.                   |
| T5  | Changelog            | **release-please** generates `CHANGELOG.md` and GitHub Releases from Conventional Commits. The app reads the same file at `/changelog`.                                                                                                                                                                     | semantic-release, changesets                                                              |
| T6  | Lint / format        | **ESLint** (flat config, next + typescript) + **Prettier** (Tailwind plugin)                                                                                                                                                                                                                                | Biome                                                                                     |
| T7  | Commit rules         | **commitlint** (config-conventional + scope list) via **lefthook** git hooks; PR titles are linted too because we squash-merge.                                                                                                                                                                             | husky                                                                                     |
| T8  | i18n                 | **next-intl**, English only for now. Strings live in `messages/<locale>.json` (nested JSON), which Loco can import and export. Locale comes from a cookie / profile setting, not the URL.                                                                                                                   | Locale-prefixed routes                                                                    |
| T9  | Cache Components     | **Off** for now. Almost every screen is behind a login and reads the session, so Cache Components would force Suspense boundaries everywhere. Revisit when performance needs it.                                                                                                                            | Next 16 template default (on)                                                             |
| T10 | Supabase keys        | New **publishable / secret** keys from day one (legacy anon/service_role keys are being retired). Migrations must include explicit `GRANT`s.                                                                                                                                                                |                                                                                           |
| T11 | UI kit               | Planned: **shadcn/ui** + Tailwind (components copied into the repo, easy to give a warm "bookish" theme). Added together with the first approved screens.                                                                                                                                                   | Mantine, Chakra                                                                           |
| T12 | Environments         | **Production only**: one Supabase project and Vercel production; Vercel preview deployments per change for the Product Owner. 2026-10-11.                                                                                                                                                                   | Separate staging Supabase project                                                         |
| T13 | Auth emails          | **Custom SMTP** for Supabase Auth before testers start (the built-in sender is heavily rate-limited). 2026-10-11. No own domain yet: use a provider that verifies a **single sender address**; move to a domain-based sender once a domain exists.                                                          | Supabase default sender                                                                   |
| T14 | Images               | User images (profile photos and readlist covers, both Later) go to **Supabase Storage**, not base64 in the database. 2026-10-11.                                                                                                                                                                            | base64 in the profile row                                                                 |
| T15 | Database deployments | Migrations are applied to production by **GitHub Actions** (`db-deploy.yml`) after a merge to `main`; credentials are stored as secrets in the GitHub `production` environment. Every PR runs a **Database** check against a temporary local Supabase (reset, lint, tests, generated types). 2026-10-11.    | Applying migrations from the development environment with a token there                   |
| T16 | UI components        | Small own components in `src/components/ui` (Tailwind), same copy-in idea as shadcn/ui; refines T11. The shadcn registry is not reachable from the development environment. Revisit in the polish sprint. 2026-10-11.                                                                                       | shadcn/ui CLI                                                                             |
